# ChatFlow 总体架构设计

## 1. 项目定位

ChatFlow 是一个面向团队协作场景的实时通信系统。

核心能力：

- 用户注册、登录、身份认证
- 单聊、群聊
- 实时消息推送
- 消息持久化
- 未读消息同步
- 在线状态管理
- 事件驱动后台处理

设计目标：通过一个完整项目实践现代企业级后端架构。

技术方向：

- Android + Jetpack Compose
- Spring Boot + Java 17
- PostgreSQL
- Redis
- Kafka
- WebSocket
- Docker Compose

# 3. 模块边界设计

ChatFlow 采用：

> Modular Monolith + DDD + Event Driven Architecture

第一阶段不拆微服务，而是在单体内部保持清晰领域边界。

## 3.1 User 用户模块

职责：

- 用户注册
- 登录认证
- JWT生成
- 用户信息管理

核心对象：

- User Aggregate
- UserId Value Object

产生事件：

```
UserRegisteredEvent
UserLoginEvent
```

---

## 3.2 Chat 聊天模块

核心业务模块。

职责：

- 创建会话
- 发送消息
- 查询历史消息
- 消息状态管理

核心对象：

```
Conversation
Message
MessageReadCursor
```

产生事件：

```
MessageCreatedEvent
MessageReadEvent
```

---

## 3.3 Notification 通知模块

职责：

- 未读提醒
- 离线通知
- 系统消息

消费事件：

```
MessageCreatedEvent
UserRegisteredEvent
```

# 5. 为什么选择这种架构

## 为什么不是微服务？

当前项目阶段：

- 用户规模未知
- 团队规模小
- 重点是掌握架构思想

直接微服务会增加：

- 服务治理成本
- 网络复杂度
- 部署复杂度

所以采用模块化单体。

---

## 为什么使用 Kafka？

Kafka负责系统内部异步事件流：

例如：

消息发送成功后：

```
MessageCreatedEvent
        |
        +--> 通知
        +--> 推送
        +--> 搜索索引
        +--> 数据分析
```

业务核心流程不会被非核心功能阻塞。

---

## 为什么使用 WebSocket？

HTTP适合请求响应：

- 登录
- 查询历史消息

WebSocket适合实时通信：

- 新消息推送
- 在线状态变化
- 实时通知

# 总结

ChatFlow 的核心架构思想：

> 用模块化单体承载业务，用DDD划分边界，用Kafka连接事件，用WebSocket提供实时体验。

这是一个从学习项目向生产级系统演进的架构路线。
